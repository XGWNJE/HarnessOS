## 一、今天建立了什么

### 1. 输入系统三通道定型

- **① 自己抓**：harness-observer skill 常驻所有 Agent 池，静默观察，只追加写 `notes/inbox/`，不打断任务、不在对话中提及。复述时机仅两个：owner 主动自检、每周评审。
- **② 主动喂**：声明式规则（declared）入口——owner 直接声明的意图型规则，豁免「重复 2 次」门槛，短陈化 ≥ 2 天 + 冲突检查，来源标 owner-declared，废止标准是 owner 改主意。
- **③ 拿现成的**：vendor/ 外部引入（原有通道，不变）。
- 关键设计：**通道按来源分（抓/喂/拿），门槛按质地分（声明式/归纳式），两个维度正交。**

### 2. 双门槛与失效测试分界

- 声明式：陈化 ≥ 2 天 + 冲突检查（防随口一说固化）
- 归纳式：重复 ≥ 2 次 + 陈化 ≥ 14 天 + 实战验证 ≥ 1 次（防个例过拟合）
- 失效测试：去掉它 Agent 会做错事 → 约束规则（global 或 skill 约束段）；不会做某事 → 技能（skills/ 独立目录）。混合笔记拆开各走各路。

### 3. 提议态

Agent 观察到 owner 重复纠正但未明说的，记 `> 类型：提议`；owner 确认后转声明式（确认日起算 2 天），否认则丢弃或留作归纳式原料。

### 4. 术语体系

声明式规则（declared）/ 归纳式规则（induced）写入 global/AGENTS.md，所有 Agent 统一说法。
