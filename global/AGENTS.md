# 全局协作规则

## 执行、工具与验证

- 严格按要求执行，不额外做、不遗漏。
- 本地 Git 提交时机由推理模型自行决定，无需确认；push 须经我明确授权。
- 需要浏览器相关能力时，优先使用 Ego，并配合 `ego-browser` 技能完成。
- 完成后按改动自动选择性价比最高的验证方式，按需进行视觉检查或较强验证，并修复本次引入的问题。
- 适时提醒我增加符合项目规模和技术栈的 CI，减少手工检查、构建和测试，提高开发效率。

## 沟通

- 默认简洁中文、大白话，必要时才用术语。
- 完成回复只说重要事项，不长篇大论；验收仅列本轮需我检查的内容和步骤。

## 界面设计与交互

- 前端 UI 以极简、极简控件和设计美感为首要原则，面向学会后的长期使用效率；允许用户初次看不懂操作，通过独立帮助页学习，不为首次无需学习而堆说明、标签或控件。
- 所有功能都必须能从首屏的固定入口进入；按重要程度与操作频率安排主次层级，高频核心操作直接可达，低频功能经次级入口按需展开，不把全部控件平铺在首屏。
- 用控件形态、图标、布局与状态表达功能，主界面只保留必要短标签、数值和反馈；原理、限制与步骤集中到帮助页，帮助入口同样首屏可达。
- 同一功能在一处只设计一套控件，同时适合鼠标和触控；统一点击 / 轻触的操作路径，以足够的命中区域和间距兼顾触控，不并排提供两套控件，不把悬停、右键或双击作为唯一操作方式。
- 自适应布局按实际容器可用宽高与控件内容所需尺寸实时判定，随窗口、缩放、字体和内容变化重算；能容纳就保留预期布局，不按屏幕分辨率、机型或固定视口断点提前切换样式。
- 空间不足时按主次渐进折叠，保留首屏始终可点 / 可触的展开入口；控件组、菜单和弹窗的整体边界不得越出可视区，长内容在受限区域滚动，不靠裁切、隐藏入口或缩小触控热区掩盖溢出。

## 文档维护

- 保持项目轻量易维护：文档简洁，只记必要内容；实现采用满足需求的简单方案，不堆叠假设性防御、抽象或冗余设计。确需额外防御或冗余时，先说明具体风险、理由和成本；可选设计不擅自扩大范围。
- 文档只写当前真实状态，保持简洁、准确、一致；定位、功能或 bug 变化同步正文、示例和索引，删除旧方案、废弃功能与变更历史。
- 完成任务、对齐文档及 Git 提交前压缩相关文档，合并重复和不同阶段的记录、删除冗余；未完成工作只简记进展、待办和阻塞，避免积压膨胀。
- README 面向人，头部遵循模板；AGENTS.md 面向 Agent。两者正文只留框架、简短总结和索引，详情放独立文档并链接。
- 修改既有文件先遵循全局规则，再遵循项目规则；不为套规范新建无必要的文档。

## 规则与安全

- 只有用户明确交代写入全局规则的内容才能加入全局规则；项目规则是否写入由 Agent 根据实际情况判断，不作统一规定。
- 每次新增全局规则，整体精简文本并适当调整分组，保留全部原意、避免歧义，无需我重复提醒。
- 密钥、token、私钥和生产配置不写入公开位置或版本历史；发现泄露须提示更换并作废旧凭据。
