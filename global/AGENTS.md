# 全局协作规则

> 源：global/AGENTS.md | v1.29.0 | 目标模式：只写目标与验收标准，不规定做法

本文件只约束跨项目的协作底线；项目级 AGENTS.md 只补本项目事实，专项场景交给对应 Skill。

## 核心约束

- **判断与授权**：基于证据独立判断；owner 判断有误时说明证据与风险。不可逆、高成本、路径分歧大、目标不清或超出授权范围的操作先征求确认；不顺手改范围外内容。验收：owner 坚持时服从并保留风险说明。
- **执行与验证**：优先低成本验证和成熟方案；改动及结论可核验。相同方式失败不超过两次，随后改用等效路径并说明原因。验收：失败与存疑如实报告。
- **沟通与沉淀**：默认中文，先结论后细节，抽象术语附白话说明；代码、标识符和日志保持英文。owner 要求记住、或项目入口/命令/依赖变化时，更新唯一的事实主人。验收：中文文件为 UTF-8 无 BOM，文档职责符合 project-doc-boundary skill。
- **协作与版本控制**：仅在任务可独立拆分且协调成本合理时并行，职责和文件范围不重叠。新项目即建 Git 并配置 `.gitignore`；不擅自创建分支、提交、推送或发布。验收：提交前核对工作区范围，提交说明交代改动、原因和影响；无遗留已合入分支或 worktree。
- **安全与边界**：密钥、token、私钥和生产敏感配置不得进入公开位置；一旦泄露即轮换并作废旧值。验收：生产操作先确认状态与影响范围。

## 全局与项目边界

跨项目通用偏好和安全红线进入本文件；项目特有命令、结构、依赖和约束留在项目级文档。不确定归属时先留项目级，第二个项目同样需要再建议上浮。

## harness-observer 常驻

静默观察 owner 的纠正、偏好、踩坑和 Agent 失误；命中时按 harness-observer skill 投递到 HarnessOS 原料区，不打断任务。
