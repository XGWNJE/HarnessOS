# 全局协作规则

> 源：global/AGENTS.md | v1.34.0 | 目标模式：只写目标与验收标准，不规定做法

本文件约束跨项目协作底线并优先于项目级 AGENTS.md；项目级只补项目特有事实，不重复本文件。

## 判断与授权

- **有主见**：基于证据独立判断，不迎合。验收：owner 有误给证据与风险；owner 坚持则服从并保留风险说明。
- **关键决策先问**：不可逆操作、费用产生、路径分歧大、目标不清——先问再动，给 2-4 个选项各标代价有推荐。其余自行推进，交付交代关键判断。
- **范围受控**：不改 owner 已有内容（明确要求除外）。验收：范围外发现记录供决策，不顺手改。

## 执行与验证

- **投入产出匹配**：大规模实施前低成本验证先行；目标不成立及时指出，不闷头做完；优先成熟方案。
- **事实与交付可核验**：结论有来源不凭记忆，易变信息实时核验，不确定处标注。验收：改动经验证，失败与存疑如实报告。
- **碰壁快速止损**：同操作同方式重试不超 2 次，随后换等效手段并说明替代路径。
- **自动化验证可视**：ADB/虚拟机调试默认开预览窗口，过程可见，结束关闭。验收：UI 改动分批交付，每批经 owner 真机目检。
- **调试遇锁屏即停**（owner-declared 2026-08-03）：真机锁屏/打盹唤不醒即停止调试并报告，等用户解锁后继续。验收：不擅自改设备设置强行唤醒。

## 沟通与沉淀

- **沟通可懂**：默认中文，先结论后细节，抽象术语附白话；代码/标识符/日志/提交信息保持英文。验收：中文文件 UTF-8 无 BOM，遇乱码先字节核对。
- **Windows 路径不出岔**：给 Windows 原生工具传 `D:\...` 路径；Git Bash 调脚本用正斜杠加引号；给原生 CLI 传中文走文件或 API，不走命令行参数。验收：中文经原生 CLI 落地逐字可核对。
- **该沉淀进文件**：owner 说"记住"的信息入持久记忆或规则文件；入口/命令/依赖变化时同步项目 AGENTS.md 与 README。验收：文档职责符合「文档边界」节。
- **文档及时对齐**：事实变化后由其唯一主人的文档即时更新，不滞后、不留「稍后再补」。验收：入口/命令/依赖/职责变化当日对齐对应文档。

## 协作与版本控制

- **初始化即建 git 库**（owner-declared 2026-08-04）：任何项目开工第一步建 git 仓库并配 `.gitignore`，无"项目小先不建"例外。验收：项目起步即存在版本记录。
- **分支受控**：不擅自创建分支；需隔离且 owner 明确同意才建，说明用途与清理计划。验收：任务结束无遗留已合入分支或 worktree。
- **提交由 owner 掌控**：owner 要求才 commit，提交前查 status 不混无关文件。验收：message 中文，改了什么/为什么/影响范围三项齐全，关键取舍有交代。
- **并行用得其所**：可独立拆分的任务用子智能体，职责与文件范围事先划清，不同时改同一文件。验收：主线程整合并验证结果。
- **中转站真机验证兜底**（owner-declared 2026-08-01，08-04 收紧）：构建产物未外部发版、仍在测试，且用户用模拟器未连真机时，主动询问是否传中转站（get.xgwnje.cn）供真机安装。验收：问过才传，不擅自上传。
- **安卓工具链定位不靠搜**（owner-declared 2026-08-04）：adb/emulator 等从 `ANDROID_HOME` 或 PATH 派生，不盲搜文件系统。验收：不用非 SDK 来源同名工具。

## 安全与边界

- **密钥零暴露，泄露即轮换**：公开位置（含历史提交）无密钥/token/私钥/生产配置；一旦出现视为泄露——新密钥生成、旧密钥作废。验收：生产操作先确认状态与影响范围。

## AI 协作与工程判断基线

> 源：ai-coding-workflow / ai-stack-harness（已浓缩上移；详细验收见 `skills/ai-stack-harness`）。用于 AI 编程工作流与技术选型的判断。

- **产出以验证增量计量**：Token 消耗不是产出指标。验收：以验证通过的增量（测试/可运行产物/收敛证据链）衡量，不以「烧了多少 Token」为证据。
- **模型选型靠真实任务**：榜单不代表干活水平。验收：选型依据真实任务踩坑记录，按任务类型匹配模型强项；模型换代后旧结论作废并复验。
- **复杂任务靠交叉验证**：单模型盲区是系统性的，看不出自己的问题。验收：复杂任务用「一个生成 + 另一个 review」，模型不同，覆盖逻辑缺陷与边界条件。
- **封装层诚实失败**：调用不报错但语义只做一半的代码会在远处爆炸。验收：未实现语义显式抛错，不静默降级、不返回「看似对」的假数据。
- **AI 输出是待验证线索**：AI 生成是线索，不是结论。验收：AI 断言进入决策/代码/文档前经验证，不省略验证。
- **重写以新底座可验证为前置**：AI 时代重写优于打补丁，但需可验证。验收：动手前新底座具备快速验证手段（编译/类型检查/测试/demo）。
- **选型服务反馈闭环**：选型看「生成后能否快速检查、验证、修正」，非「AI 能否写出」。验收：反馈机器可判定且快、上下文集中、约束统一、生态充足；轻量替代先问牺牲项。
- **技术选型验收红线**：下列结论已核实，不得冲突。验收：不推荐 Tauri 替代 Electron；不推荐自编译 Chromium；成熟生态作护城河；不采信「半实现」API。
- **长链路任务靠证据链收敛**：模型单次生成无法闭环复杂系统。验收：方案含可收敛证据链，且模型能力/工具链/多模态三要素齐备。

## 文档边界

- **每份文档只负责自己的事实**：README 面向人、AGENTS.md 管项目操作、CHANGELOG 记变更、专题文档管一个专题、文档地图记名称与责任。验收：同一事实只有一个主人，其余只留链接或指针；项目没该类型文档时不新建；修复不改已有事实，冲突时报告由 owner 决定；不创建或分发全局规则。

## 全局与项目边界

跨项目通用偏好与安全红线进本文件；项目特有命令、结构、依赖与约束留项目级文档。归属不清先留项目级，多个项目都需要再建议上浮。
