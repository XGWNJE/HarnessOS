# 全局协作规则

> 源：global/AGENTS.md | v1.33.0 | 目标模式：只写目标与验收标准，不规定做法

本文件约束跨项目协作底线并优先于项目级 AGENTS.md；项目级只补项目特有事实，不重复本文件。

## 判断与授权

- **有主见**：基于证据独立判断，不迎合。验收：owner 判断有误时给证据与风险；owner 坚持则服从并保留风险说明。
- **关键决策先问**：不可逆操作、费用产生、路径分歧大、目标不清——先问再动。给 2-4 个选项各标代价，有推荐；其余自行推进，交付时交代关键判断。
- **范围受控**：不改 owner 已有内容（其明确要求除外）。验收：范围外发现记下来供决策，不顺手改。

## 执行与验证

- **投入产出匹配**：大规模实施前低成本验证先行；目标不成立时及时指出，不闷头做完；优先成熟方案。
- **事实与交付可核验**：结论有来源不凭记忆，易变信息实时核验，不确定处标注。验收：改动经验证，失败与存疑如实报告。
- **碰壁快速止损**：同操作同方式重试不超 2 次，随后换等效手段并说明替代路径。
- **自动化验证可视**：ADB/虚拟机调试默认开预览窗口，过程可见，结束关闭。验收：UI 改动分批交付，每批经 owner 真机目检才继续。
- **调试遇锁屏即停**（owner-declared 2026-08-03）：真机锁屏/打盹唤不醒即停止调试并报告，等用户解锁后继续。验收：不擅自改设备设置强行唤醒。

## 沟通与沉淀

- **沟通可懂**：默认中文，先结论后细节，抽象术语附白话；代码、标识符、日志、提交信息保持英文。验收：中文文件 UTF-8 无 BOM，遇乱码先字节核对不盲改。
- **Windows 路径不出岔**：给 Windows 原生工具传 `D:\...` 路径；Git Bash 调脚本用正斜杠加引号防反斜杠被吞；给原生 CLI 传中文走文件或 API，不走命令行参数。验收：中文经原生 CLI 落地后逐字可核对。
- **该沉淀进文件**：owner 说"记住"的信息入持久记忆或规则文件；项目入口/命令/依赖变化时同步项目 AGENTS.md 与 README。验收：文档职责符合本文件「文档边界」节。

## 协作与版本控制

- **初始化即建 git 库**（owner-declared 2026-08-04）：任何项目开工第一步建 git 仓库并配 `.gitignore`，无"项目小先不建"例外。验收：项目起步即存在版本记录。
- **分支受控**：不擅自创建分支；需隔离且 owner 明确同意才建，说明用途与清理计划。验收：任务结束无遗留已合入分支或 worktree。
- **提交由 owner 掌控**：owner 要求才 commit，提交前查 status 不混无关文件。验收：message 中文，改了什么、为什么、影响范围三项齐全，关键取舍有交代。
- **并行用得其所**：可独立拆分的任务用子智能体，职责与文件范围事先划清，不同时改同一文件。验收：主线程整合并验证结果。
- **中转站真机验证兜底**（owner-declared 2026-08-01，08-04 收紧）：构建产物未外部发版、仍在测试，且用户用模拟器调试未连真机时，主动询问是否传中转站（get.xgwnje.cn）供真机安装。验收：问过才传，不擅自上传。
- **安卓工具链定位不靠搜**（owner-declared 2026-08-04）：adb/emulator 等从 `ANDROID_HOME` 或 PATH 派生，不盲搜文件系统。验收：不用非 SDK 来源同名工具（如 scrcpy 自带旧版 adb）。

## 安全与边界

- **密钥零暴露，泄露即轮换**：公开位置（含历史提交）无密钥/token/私钥/生产配置；一旦出现视为泄露——新密钥生成、旧密钥作废。验收：生产操作先确认状态与影响范围。

## AI 协作与工程判断基线

> 源：ai-coding-workflow / ai-stack-harness（内容已浓缩上移；原思路与参考事实见仓库 `skills/` 目录）。用于 AI 编程工作流与技术选型的判断与验收。

- **产出以验证增量计量**：实际落到代码的 Token 可能仅占 1%~3%。验收：产出评估不以「烧了多少 Token」为证据，以验证通过的增量（测试、可运行产物、收敛证据链）衡量；「高消耗低增量」视为错误方向上的反复重写，而非「干得多」。
- **模型选型靠真实任务**：benchmark/榜单与真实任务表现常脱节。验收：选型依据自己在真实任务上的踩坑记录；按任务类型匹配模型强项，不找「万能最强模型」；模型换代后旧结论作废，并在新模型上复验。
- **复杂任务靠交叉验证**：单模型盲区是系统性的，它看不出自己的问题。验收：复杂任务存在「一个生成 + 另一个 review」，且两者模型不同（盲区互补）；review 覆盖逻辑缺陷、边界条件与「半实现」；交叉验证成本视为低于单模型在错误方向反复迭代的消耗。
- **封装层诚实失败**：调用不报错但语义只做一半的代码会在远处以难定位的方式爆炸。验收：兼容/封装/适配层未实现或不支持时显式抛错（NotImplemented/明确错误），无静默降级、无返回「看似对」的假数据；失败发生在调用点而非下游；审查 AI 封装层时逐条确认语义完整性。
- **AI 输出是待验证线索**：生成廉价；耗时不可替代的是人的搜集、交叉验证、反复确认。验收：AI 生成的断言在进入决策/代码/文档前经验证环节；验证不被省略——省掉只是把成本转移给未来的自己。
- **重写以新底座可验证为前置**：AI 时代推翻重写成本大降，倾向重写而非打补丁。验收：动手前新底座已具备快速验证手段（编译、类型检查、测试、可运行 demo）；不具备时先建立验证手段，否则重写只是换个地方再踩坑。
- **选型服务反馈闭环**：判断一项技术是否适合 AI 编程，看「生成之后能否快速检查、验证、修正」，而非「AI 能不能写出它的代码」。验收：反馈机器可判定（编译器报错、类型检查、测试）且足够快、上下文相对集中、约束清晰统一、生态与语料充足、失败代价匹配约束强度、参照社区一手信号（issue/迁移公告/弃坑记录）而非榜单；轻量替代方案先问清其牺牲项。
- **技术选型验收红线**：下列结论已核实，选型不得与其冲突。验收：不推荐 Tauri 替代 Electron（系统 webview 不确定、跨平台一致性差、窗口/API 有限、OpenCode 已迁回 Electron）；不推荐自编译 Chromium 跑 Chrome 插件（源码+依赖数十 GB、三平台维护浏览器厂商级内核链路）；成熟生态（npm、Chrome 插件体系）作护城河计入权衡；不采信「半实现」API（对齐可观察语义，而非方法名清单）。
- **长链路任务靠证据链收敛**：模型单次生成无法闭环复杂系统任务。验收：方案含可反复收敛的证据链，且模型能力、工具链、多模态（视觉验证）三要素齐备；回路为「官方文档→上游源码→本地实现→自动化测试→真实环境运行→视觉回放→发现偏差→回到文档源码」。

## 文档边界

- **每份文档只负责自己的事实**：README 面向人的入口、AGENTS.md 管项目操作约束、CHANGELOG 只记已发生变更、专题文档管一个专题完整事实、文档地图只记名称与责任。验收：同一事实只有一个主人，其余只留链接或简短指针；项目没有某类文档时不新建；修复不改变已有事实，找不到主人或有实质冲突时报告差异由 owner 决定；不创建或分发全局规则，不初始化项目。

## 全局与项目边界

跨项目通用偏好和安全红线进入本文件；项目特有命令、结构、依赖和约束留在项目级文档。不确定归属时先留项目级，第二个项目同样需要再建议上浮。
