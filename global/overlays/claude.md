## 协作（补充）

- 对适合并行拆分的任务优先使用子智能体，提高执行效率；典型场景包括项目很大、历史构建杂乱、需要同时排查多个模块/日志/测试失败/迁移路径
- 使用子智能体前先划清每个子智能体的职责、文件范围、读写权限、等待条件和汇总格式；写代码时避免多个子智能体同时修改同一文件或同一模块，最终由主线程整合和验证
- 关键取舍用 2-4 个选项澄清，标注推荐项和代价

## 代码与文字

- 代码默认用英文：变量、函数、类、文件、目录、注释、日志、错误、测试、提交信息、配置键
- 中文只用于用户可见文案、README、CLAUDE.md、设计/部署/操作说明
- 不为既有中文标识符做无关重构；只在本次范围避免新增中文代码内容

## 文档边界（详细版）

- 文档要先分清读者和责任，避免 README、CLAUDE.md、设计/部署/操作文档大段重复
- README 默认写给人看：项目用途、快速开始、日常入口、常用命令、安全提醒、哪些文件不要碰/不要提交
- 若项目主要由 Agent 维护，README 更要减轻用户阅读压力；细节规则放 CLAUDE.md
- CLAUDE.md 默认写给 Agent 看：项目边界、文件职责、验证步骤、危险操作、敏感信息、自动化限制、提交/发布规则、跨项目边界
- 专题细节放专题文档；README 只保留摘要和链接
- 发现重复内容时，保留在最适合读者的文档里，其他文档改为摘要或链接
- 分工不是固定模板；不变原则是先划清读者、用途和维护责任

## 文档同步

项目发生以下变动时，同步检查 README 与项目级 CLAUDE.md，并按文档边界拆分内容：
- 构建、运行、测试、部署命令变化
- 目录结构、模块职责、入口点变化
- 新依赖、框架、外部服务或运行环境变化
- 配置方式、环境变量、密钥获取或本地准备步骤变化
- README 快速开始与实际流程不一致

## Git

- 不主动执行 commit；只有用户明确要求时才提交
- 当发现当前进度适合保存一个提交点时，主动提醒用户可以提交，并简要说明建议提交的范围
- 提交前检查 git status，不要混入无关文件
- 不覆盖、回滚或丢弃用户已有改动，除非用户明确要求
- commit message 用中文，简洁说明目的

## sing-box 路由规则顺序

- TUN 模式下 `protocol: dns → hijack-dns` 必须排在所有路由规则第一位（紧跟 `sniff`），不允许任何进程级规则出现在它前面。否则发往私有 IP（如路由器）的 DNS 查询会绕过劫持直连到路由器，拿到 ISP 污染结果。

## Windows 编码（详细版）

- 仓库文本默认 UTF-8 无 BOM
- PowerShell 读中文文本显式用 UTF-8，例如 `Get-Content -Encoding UTF8 README.md`
- 写文本优先用 Edit 工具；必须用 PowerShell 写入时显式 `-Encoding UTF8`
- 看到 `鏄`、`涓`、`锛`、`â€"`、`` 等疑似乱码，先停下并用 UTF-8 字节核对，不能把乱码当真实内容编辑
- 修改中文 Markdown/JSON/JS/TS/CSS/配置后，确认无新增乱码、替换字符或异常 BOM
