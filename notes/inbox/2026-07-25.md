## 文档偏移纠正时机分层：commit/push 前为硬卡点，其余按性价比
> 日期：2026-07-25
> 场景：AI 编程过程中文档（README、AGENTS.md、CHANGELOG、注释、skill 源）与代码实际行为漂移，纠正时机不稳定、不完整
> 类型：声明式原料（owner-declared）
> 来源项目：D:\ObjectCode\HarnessOS
> 陈化截止：2026-07-27（满 2 天后可写入 global/AGENTS.md）
> 冲突检查（2026-07-25 已做）：无冲突。global「文档维护」段（命令/结构变化时对齐全档）是本规则的子集；grsai-image-gen 内 drift 条目为 skill 内部 API 对齐，无关。

规则草案（owner 已定核心，细节经讨论成型）：

- **硬卡点（无例外）**：执行 `git commit` / `git push` 前，必须全量排查本次改动涉及的所有文档偏移并清零——不带已知偏移入库。覆盖范围：项目 README、AGENTS.md、CHANGELOG、代码注释/docstring、skill 源文件及 CHANGELOG 记账。
- **软时机（按性价比）**：
  - 改动当时，偏移文档就在手边（同文件注释、正在编辑的文档）→ 顺手纠正，成本最低。
  - 偏移文档不在手边、纠正会打断当前任务 → 最小动作是**记录**（记入待纠偏清单/TODO），到 commit 卡点统一清零；禁止"先记着回头改"却不落字。
- 机制思路（呼应同日 inbox 条目"纯文档无强制加载"的教训）：规则文字只能要求 agent 自觉，稳定性差的环节应补机制——如 pre-commit hook 做文档体检提醒，或项目已有的体检脚本（如 HarnessOS 的 `sync.py --check`）纳入 commit 前流程。机制形态待写入时定。

进展（2026-07-26）：owner 确认方向并指示试点先行，暂不建议通用 hook 流水线。试点已落地 `hooks/pre-commit`（commit 前提醒文档偏移清零 + `sync.py --check` 拦截漂移），安装 `git config core.hooksPath hooks`，闭环验证通过（干净=0 / 漂移=1 / 恢复=0）。试点首问题：hook 环境 GBK 乱码，已在 hook 内显式 export UTF-8 修复。详见 CHANGELOG 2026-07-26。
