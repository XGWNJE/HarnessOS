## Compose M3 AlertDialog  tonalElevation 会把 primary 色叠到容器上
> 日期：2026-07-26
> 场景：Kotlin / Jetpack Compose Material3 / Android UI 统一改造
> 类型：归纳式原料
> 来源项目：D:\ObjectCode\Vigil
> 重复计数：1

观察事实：暗色主题（primary=酸橙绿）下用 `AlertDialog(containerColor=近黑)` 并自加 8dp 描边边框，真机渲染成橄榄色大圆角双框。当时判断是 containerColor 没生效，实际是 M3 默认 `tonalElevation=6dp` 把 primary 按比例叠加到容器色上，且默认 28dp shape 与 8dp 边框错位。修复：显式 `shape` + `tonalElevation=0.dp`。同 bug 潜伏在上一轮"已验收"的旧弹窗里——因为那轮验收没人实际打开过它。教训：弹窗类 UI 验收必须逐个真机打开，不能只看主页面；自定义 M3 弹窗先归零 tonalElevation 再谈容器色。

## Edit 工具对 CRLF 文件的 old_string 匹配持续失败 → sed 行号兜底
> 日期：2026-07-26
> 场景：Kimi Code Edit 工具 / Windows CRLF Kotlin 源文件
> 类型：归纳式原料
> 来源项目：D:\ObjectCode\Vigil
> 重复计数：1

观察事实：目标文件 Read 视图每行尾显示 `\r`（纯 CRLF），按文档在 old_string 里先后用 LF、显式 `\r` 转义各试 3 次均报 not found（疑似传输层把 CR 规范化掉）。放弃 Edit，改 `sed -i '99,104d'` 按行号删除一次成功。教训：CRLF 文件的整块删除/替换别在 Edit 上反复耗，重读确认行号后 sed 一次到位；单行无 CR 歧义的小改动仍可先试 Edit。

## 自定义文本按钮只给字形大小 clickable，被 owner 实测"不能点"
> 日期：2026-07-26
> 场景：Compose UI / Agent 自身语义失败（假设错误）
> 类型：归纳式原料
> 来源项目：D:\ObjectCode\Vigil
> 重复计数：1

观察事实：自绘返回按钮用 `Text("←").clickable(...)`，触控区只有字形约 20dp，agent 自测用 adb 精确点坐标"通过"了，owner 手指实测点不中。根因：假设"clickable 挂上即可"，违反了最小触控目标 48dp 的平台常识；且 agent 的 adb 坐标点验掩盖了真实手感问题。防再犯：自定义 clickable 文本/图标控件一律外包 ≥48dp 触控盒再对齐字形；验收触控类改动要用接近手指的尺寸思维自审，不能只信坐标命中。
