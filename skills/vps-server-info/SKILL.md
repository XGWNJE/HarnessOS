# VPS 服务器信息

当前常规 SSH 别名为 `server-infra-tokyo`。连接前读 [核验快照与命令](references/current-state.md)；它是有日期的观察，不代替实时状态。服务器资源、生命周期与连接资料的事实源在私有仓库 `Wenje-Server/Server-infra`，本技能只保留脱敏入口与必要摘要。

## 操作边界

- 先查资源清单与 SSH 配置，使用规范别名；旧美国节点已排除日常检查，不沿用 `xgwnje`、`visionguard` 等旧兼容名，也不探测退役服务。真实地址、端口、用户与私钥位置只从本机 SSH 配置读取，不在公开技能保存。
- 读服务状态不授权修改配置、部署、reload 或 restart；实际操作遵循当前用户授权和目标项目规则。其他项目引用服务器资料时，不顺带运行会写回资料的维护模式。
- 发布、证书、Nginx 变更前核对实际生效配置；部署前核对 CPU、内存与磁盘余量。清理前核实业务、回滚点和发布脚本依赖。
- 快照超过 30 天或与现场矛盾时，明确标出过期范围并做本次任务所需的只读核验，不用旧记录补成当前事实。
- IP、SSH 私钥、证书私钥、应用密钥、代理节点与订阅凭据不进入输出、提交或公开文档；不回显完整环境、服务启动参数或生产配置。

## 连接与失败处理

1. 内部解析 `ssh -G server-infra-tokyo`，只确认别名、连接参数和指定私钥可用，不输出敏感值；不遍历磁盘寻找密钥。
2. 用已有可信主机记录和密钥做一次只读连接，设置 `BatchMode=yes`、`ConnectTimeout=8`、`StrictHostKeyChecking=yes`。
3. 连接异常时报告脱敏原因；同一方式最多重试一次，不反复尝试旧节点或猜测新连接资料。缺少别名或密钥时向用户说明缺口。
4. 服务不存在、健康检查失败或资料冲突时，如实区分快照与实测结果；未验证的链路和业务功能不报告为通过。
