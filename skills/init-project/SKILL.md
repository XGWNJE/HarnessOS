# 项目规则初始化

目标：为当前项目建立或重整 `AGENTS.md`，使其与全局规则 `C:/Users/Administrator/AGENTS.md` 分工明确、不重复、不矛盾。

## 原则

- 全局规则文件（`~/AGENTS.md`）是所有 agent 的最高优先级通用规则，**唯一事实来源（唯一可靠依据）**，项目级文件不得复制其内容。
- 项目级 `AGENTS.md` 只写项目特有事实：项目边界（范围/职责）、关键路径与命令（必要步骤和对应命令）、验证矩阵（变更类型对应的最小验证清单）、发布流程、文档地图（文档导航/各文档负责内容）、不可违反的项目铁律。
- 风格：中文祈使句、"不得/必须/优先"式约束、短句；铁律放最前，细节指向 docs/ 而非内联长段（直接写在文件里的长段落）。

## 步骤

1. **读取全局规则**：先读 `C:/Users/Administrator/AGENTS.md`，确认哪些主题已被全局覆盖（角色、决策自主权（谁做决定、决定范围）、验证、安全、文档边界（文档分工范围）等），项目文件不再重复。
2. **调查项目事实**（不凭记忆）：
   - 读 `README.md`、`package.json`（或对应构建清单（构建配置文件））、现有 `AGENTS.md`、`docs/` 目录结构；
   - 确认构建/测试/验证命令、目录职责（每个目录负责什么）、发布流程、持久数据位置（数据保存位置）；
   - 已有项目级 skill（`.agents/skills/`）和脚本入口（脚本启动文件）要登记。
3. **识别项目铁律**：从历史文档、`docs/decisions/`、用户口述中提炼"不可违反"约束（保留能力不得删除、数据不随发布替换、禁止提交的内容等），逐条编号。
4. **起草项目 AGENTS.md**，推荐结构：
   - 一句话项目定位；
   - `## 铁律（不可违反）`：编号列表；
   - `## 关键路径与命令`；
   - `## 最小验证矩阵`（变更类型 → 最小验证，表格）；
   - `## 工作规则`：项目特有的协作约定；
   - `## 发布`（如有发布流程）；
   - `## 文档地图`：每份文档负责什么事实，注明"事实变化时只更新负责该事实的文档"。
5. **审核后写入**：先把草案展示给用户审核，确认偏好问题主动询问；用户确认后再写入文件。
6. **清理漂移（消除不一致）**：检查旧版规则、其他 agent 的规则副本（如 `.codex/`、`.claude/` 下的 AGENTS.md），提示用户合并或改为指针（指向另一个文件的引用），避免多份并存漂移（内容彼此偏离）。

## 验收

- 项目 AGENTS.md 中不出现全局规则已覆盖的通用条目；
- 每条规则可被验证或指向可验证的事实（命令、路径、文档）；
- 铁律不超过 10 条，超出部分降级（降低级别）为普通工作规则。
