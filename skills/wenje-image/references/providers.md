# 服务选型、模型与路由

本文件是"用哪个服务、哪个模型、什么价格"的事实源。价格与可用模型属易变信息，2026-09 调研所得只作路由参考，**不是报价**；涉及成本决策前先核验 Grsai 控制台。

## 当前默认：Grsai

Grsai 是**聚合/中转服务**（不是模型厂官方）：把 Gemini `nano-banana` 系列与 OpenAI `gpt-image` 系列转成一套统一 API，国内直连，价格显著低于官方。本 skill 只实现了这一个 provider。

它适合：草稿、批量试图、个人非关键产出——即"便宜比稳定更重要"的场景。
它不适合：需要官方 SLA 与合规凭证、需要开票、或产出直接交付客户的场景。

### 已知的实测行为（与文档不一致，按这里写代码）

- 密钥无效**不是**文档写的 401：`/v1/api/generate` 在 `replyType=json` 下返回 **HTTP 400 + `{"id":"","status":"failed","error":"apikey error"}`**，在 `replyType=async` 下返回 **HTTP 200 + 空响应体**。后者会误导调用方，所以引擎在响应为空时会补一次零费用鉴权探测再定性。
- 结果图片 URL **只在服务端保留 2 小时**（查询接口的 404 消息为 `result not exist, valid for 2 hours`）。必须下载落盘，别把 URL 当长期产物。
- 内容违规**不退还积分**；只有系统错误才退。所以"换个模型重试同一提示词"没有意义。
- 查询接口 `/v1/api/result` 不校验密钥，用它判断密钥是否有效是无效的；判断鉴权要用 `/v1/chat/completions` 配一个不存在的模型名（不产生费用），引擎的 `status --verify` 就是这么做的。

## 可用模型（限定集）

**只有下列 5 个模型可用**，其余一律拒绝——这是 owner 2026-09-13 指定的限定集，不是建议。价格与规格能力取自 Grsai 控制台模型页（同日核验），易变，成本决策前重新核验。

| 模型 | credits | 参考价/张 | 支持的 imageSize | 定位 |
|---|---:|---|---|---|
| `gpt-image-2.5` | 600 | ￥0.03 | **仅 1K** | 最便宜的草稿档 |
| `gpt-image-2.5-flare` | 2000 | ￥0.10 | 1K / 2K / 4K | 日常默认，速度优先 |
| `gpt-image-2.5-sunburst` | 2400 | ￥0.12 | 1K / 2K / 4K | 质量与编辑精确度优先 |
| `nano-banana-2` | 1200 | ￥0.06 | 1K / 2K / 4K | 唯一支持极端比例的通道 |
| `nano-banana-pro-4k-vip` | 18000 | ￥0.90 | **仅 4K** | 4K 专用，昂贵，只在点名时用 |

规格能力是硬约束而非偏好：引擎按它决定档位，绝不把模型没有的档位硬塞进去。`gpt-image-2.5` 没有 4K，要 4K 只能落到 1K 或换模型；`nano-banana-pro-4k-vip` 没有 1K/2K，要 1K 会落到 4K。两种情况都会写进 `size_note`。

背景：`gpt-image-2.5` / `-flare` / `-sunburst` 是 OpenAI 2026-09-08 发布的 GPT-Image-2.5 家族，Grsai 按同名前缀转出——基础款最便宜且只有 1K，flare 偏速度，sunburst 偏质量。

## 路由规则

**先看用户声明了什么**：用户在请求里点名的模型、档位、比例、尺寸一律照做，不替换成更便宜或更保险的选项，也不为此反问。下表只用于用户**没点名**的部分——那些由 Agent 直接定，同样不反问用户。

档位 → 模型（**只在用户没点名模型时生效**）：

| 档位 | 模型 | 何时用 |
|---|---|---|
| `draft` | `gpt-image-2.5` | 草稿、快速预览、用户明确要省钱（￥0.03，仅 1K） |
| `standard` | `gpt-image-2.5-flare` | 默认；物料、插画、封面 |
| `premium` | `gpt-image-2.5-sunburst` | 用户要求更高质量或精确改图，且接受成本 |

两条自动改选（同样只在用户没点名模型时生效，不反问用户）：

- 比例为极端比例 `1:4`/`4:1`/`1:8`/`8:1` → 改用 `nano-banana-2`，只有它支持。
- 要求 4K → `standard` 档的 `gpt-image-2.5-flare` 本身支持 4K，保持不动；`draft` 档的 `gpt-image-2.5` 只有 1K，会由规格落档机制转到 1K 或停在 1K。
- 用户点名了模型则不做任何改选：比例不被该模型支持就直接报错并列出可选值，由调用方决定改比例还是换模型。

### 风格倾向：先定"哪一系"，再定"哪个价位"（owner 声明）

没点名模型时，先按用户要的效果选**系**，再按档位选**具体模型**：

| 用户要的效果 | 优先的系 | 具体模型 |
|---|---|---|
| 自然、写实；扩展像素增加细节（放大补细节、往外扩画面、真实材质与质感，如皮肤/头发/织物/风景） | **Banana 系** | `nano-banana-2`；同时要求最高质量且接受 ￥0.90 时才用 `nano-banana-pro-4k-vip` |
| 更多创意、更强的编辑能力与效果（改图、特效、风格化、构图再造、指定局部改动） | **Image 2.5 系** | 按档位：`gpt-image-2.5`（草稿）/ `gpt-image-2.5-flare`（默认）/ `gpt-image-2.5-sunburst`（质量优先） |

依据：Banana 系更偏真实写实，Image 2.5 系创意与编辑能力更强。

边界：①这是 **owner 2026-09-13 声明的选型倾向**，不是可核验的客观结论，也没有做过对照实验；②只在用户**没点名模型**时生效，用户点名或提出与倾向相反的要求时，一律以用户要求为准；③两系都能做对方擅长的事，这条只决定"默认先试哪个"，不是能力边界。

比例 → 默认尺寸：

| 场景 | ratio | size |
|---|---|---|
| 头像 | `1:1` | `1K` |
| 手机壁纸 | `9:16` | `2K` |
| 桌面壁纸 | `16:9` | `2K` |
| 社交方图 | `1:1` | `1K` |
| 文章封面 | `16:9` | `1K` |
| Banner | `21:9` | `1K` |
| 海报 | `2:3` | `2K` |
| 未指定 | `1:1` | `1K` |

参数兼容性（引擎已按此换算与校验）：

- `nano-banana-2`、`nano-banana-pro-4k-vip` 用 `aspectRatio` 比例串 + `imageSize`；支持 `auto` 与 `1:1`/`16:9`/`9:16`/`4:3`/`3:4`/`3:2`/`2:3`/`5:4`/`4:5`/`21:9`，`nano-banana-2` 另支持 `1:4`/`4:1`/`1:8`/`8:1`。
- `gpt-image-2.5` 家族用 `aspectRatio` **像素串**（按 `grsai-api-docs.md` 的比率表换算）；比例是 `auto` 时不下发该字段，交给服务端决定。
- 像素串约束：两边都是 16 的倍数、最长边 ≤ 3840、长短比 ≤ 3:1、总像素 655360~8294400。因此 `1:3`/`3:1` 这类比例没有 4K 档，遇到会直接报错并列出可用档位。
- ✅ **像素串形式已实测成立**（2026-09-13 付费实测）：`gpt-image-2.5` 用 `aspectRatio: "1024x1024"`、`gpt-image-2.5-flare` 用 `aspectRatio: "3840x2160"`（4K）均成功出图，`build_payload()` 的 `pixels` 分支无需改动。此前"该家族可能只收比例串"的推断已排除。
- ✅ **参考图 data URI 已实测成立**（同日）：`images` 数组传 `data:image/png;base64,…` 时参考图被真实采纳——实测把蓝圆改成绿圆、且中心白方块按指令保留，说明不是被忽略后重新生成。
- 一条出图尺寸观测：`gpt-image-2.5` 请求 1K（像素串 `1024x1024`）实际产出 **1254×1254**；`gpt-image-2.5-flare` 请求 4K 精确产出 **3840×2160**。基础款可能按模型原生尺寸出图、不严格照抄像素串；需要精确尺寸时以实测为准。
- `nano-banana-pro-4k-vip` 未做过真实调用：单次 ￥0.90，其参数形式与已实测通过的 `nano-banana-2` 同族。owner 2026-09-13 决定不为它单独付费验证，**此条不再是待办**；真实用到时第一次调用即可确认。
- `/v1/api/generate` 的参考图字段是 `images`；OpenAI 兼容端点 `/v1/images/generations` 用的是 `image`。

## 替代方案（成本决策时再看）

同为个人技能，替代品分两类。价格是 2026-09 调研值，需实时核验。

| 方案 | 类型 | 约价/张 | 换取的收益 | 代价 |
|---|---|---|---|---|
| **Grsai**（现状） | 聚合中转 | ￥0.03~0.90 | 最便宜、国内直连、模型统一 | 非官方、无 SLA、违规不退款、可能涨价或中断 |
| 火山方舟 Seedream 4.0 | 官方 | ￥0.20 | 官方稳定性、中文文字与排版强、可开票 | 贵约 7 倍、需实名与方舟账号 |
| Google Gemini 官方（nano banana 系列） | 官方 | $0.039~0.134 | 官方稳定性、模型最新 | 需海外支付与网络，单价高约 10 倍 |
| fal.ai / OpenRouter 等海外聚合 | 聚合 | $0.018~0.13 | 模型覆盖广、英文生态好 | 需海外支付与网络，延迟高 |

**建议**：默认保留 Grsai 做草稿与批量；把"要交付给别人/要开票/提示词反复违规"当作切换信号。真要换，换成官方（Seedream 或 Gemini）而不是另一个中转，否则只是把同一类风险换个名字。

## 更换 provider 的条件

引擎目前只有 `grsai` 一个实现。新增 provider 需要：

1. 在 `scripts/wenje_image.py` 增加该服务的提交、轮询、结果解析与错误语义映射（映射到统一的退出码）。
2. 在设置页与 `status` 中暴露选择；配置里 `provider` 字段是预留的切换点。
3. 不要为未实现的服务留静默降级分支——请求未知 provider 时直接报错，不回退到 Grsai 出图。
