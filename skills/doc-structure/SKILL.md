# 文档结构：职责边界、模板与自动验收

来源：owner-declared（2026-08-01，全局规则「README 面向人，专题细节在专题文档，其余文档只留链接」的落地机制）
写法：目标与验收标准为主体 + 参考流程为锚点——文档模板是硬标准（跨项目统一靠它），做法细节由模型按情境自决。

## 文档职责边界表（硬标准）

每个文档只有一个主人，内容按边界分配，不重复、不越界：

| 文档 | 面向谁 | 职责（只写这些） | 禁止出现 |
|---|---|---|---|
| README.md | 人（含陌生人） | 项目干什么（概念级）、怎么开始（一条命令+链接）、文档导航 | 操作细节、命令清单、流程表格、模板格式 |
| AGENTS.md | Agent | 项目全部操作规则：铁律/关键路径命令/验证矩阵/工作规则/文档地图 | 宣传文案、概念性介绍 |
| CHANGELOG.md | 人+Agent | 加工历史（新增/修订/废止/框架），只新增不改旧 | 规划、未落地内容 |
| 专题文档（vendor/SOURCES.md 等） | 人 | 单一专题事实（如第三方来源登记） | 专题之外的内容 |
| notes/ | 人（自己） | 原料，粗糙允许 | 无（已加工即销毁） |

**堆积的根源是职责越界**：新内容写进文档时先问「它属于哪个文档的主人」——属于操作规则→AGENTS.md，属于概念→README，属于历史→CHANGELOG；README 不是默认落点。

## 模板

### README 模板（面向人）

```
# 项目名

一句话：项目是什么（目标句）。

## 项目干什么
概念级说明（3 条以内，每条约 1-2 行，不展开机制细节）

## 界面展示（产品型项目必填）
有明确产品性质（用户可交互界面）的项目必须放真机截图，动画 GIF 更佳：

![界面截图](screenshots/main.png)

![关键交互演示](screenshots/demo.gif)

## 怎么开始
- 一条命令/一个入口（细节一律「详见 AGENTS.md」）

## 文档地图
- README.md：本文件，面向人——项目干什么、怎么开始
- AGENTS.md：面向 Agent 的完整操作规则（全部细节都在这里）
- CHANGELOG.md：加工历史
- （其他专题文档各一行）
```

### AGENTS.md 模板（面向 Agent）

结构与内容体系的唯一主人是 init-project skill（推荐结构、常驻职责条目、铁律受控等以它为准）。本 skill 只管它在边界表中的分工：面向 Agent，放项目全部操作规则，禁止宣传文案与概念性介绍。

## 自动验收标准（全部可机器检验）

- `python scripts/check_docs.py` 退出码 0：无操作细节禁止词、含文档导航段（行数不设硬上限，owner 2026-08-01 决策——冗余按智能判断）
- **易变信息对齐**（owner 2026-08-04 归属拍板）：徽章计数、版本号引用等易变信息的对齐与漂移纠正是本 skill 职责；README 出现 shields Skills 计数徽章时，数字须等于 skills/ + vendor/ 下含 SKILL.md 的目录数（check_docs.py 机械校验，徽章不存在或无 skills//vendor/ 目录时不生效）
- README 与 AGENTS.md 无重复段落（同一事实只在一个文档出现）
- 文档地图中的每个文档存在且有明确职责
- 改文档后 `sync.py --check` 无漂移（HarnessOS 仓库）

## 智能验收标准（模型判断，机器不可自动判定）

- **结构正确**：用浏览器/渲染器目检 README 渲染——HTML block（`<div>` 等）内部及前后的 markdown 必须有空行分隔，否则整段被吞为纯文本（2026-08-01 实测踩坑：压缩空行删掉 `<div align="center">` 后空行，头部标题/badge 全部失效）；表格必须完整成块（表头行 + 分隔行 + 数据行连续，多表之间留空行分隔，否则两张表被合并解析）。
- **无明显冗长**：同一事实不重复表述、无赘述、段落句子不重复堆砌；内容确实需要长就允许长（功能说明/权限表等事实性内容不受行数约束），但重复与空话要删。
- **产品型项目**（有用户可交互界面，非纯库/规则/脚本仓库）：README 必须含至少一张真机截图（真实运行画面，非示意图/线框图）；关键交互流程有动画 GIF 更佳。真机截图 = 实际运行中拍摄/截取，不是 mockup。

## 参考流程（锚点）

1. **触发**：提交被 pre-commit 拦截（提示 doc 体检失败）、或 owner 要求整理文档。新项目初始化不走本 skill——走 init-project。
2. **诊断**：判断项目是否产品型（有 UI 界面 → 产品型，README 必须含真机截图；纯库/规则/脚本仓库 → 非产品型，不需要截图）。读 README/AGENTS.md/文档地图 → 对照边界表逐段标出「属于谁」：越界的（操作细节在 README）→ 标记移入 AGENTS.md；重复的 → 保留文档地图指定的那个主人；堆积的（明显冗长/重复）→ 压缩为概念级。
3. **重构**：按模板重写，被移除的细节确保已在 AGENTS.md（或专题文档）存在，不丢事实。
4. **自动验收**：跑 `python scripts/check_docs.py`（其他项目：`--readme <路径>` 指定），再跑 `sync.py --check`（HarnessOS 仓库）；全绿才算完成。
5. **其他项目复用**：doc-structure skill 已发布到各 Agent 池，任何项目引用本 skill 即用同一套模板与验收标准 → 多项目同风格。机械检查可调用 HarnessOS 的 `scripts/check_docs.py --readme <其他项目 README>`，或复制该脚本到项目内接入 pre-commit。

## 失效模式

| 场景 | 处理 |
|---|---|
| 机械检查通过但文档语义重复（机器查不出） | 按边界表逐段人工核对，把重复内容移到唯一主人；这是 skill 的智能部分，机械部分管不住 |
| 禁止词误报（README 必须出现某操作词） | 在 check_docs.py 禁止词清单中登记移除，并在验收标准注明理由；不绕过整体检查 |
| README 渲染结构崩坏（标题/表格/badge 变纯文本） | 最常见是 HTML block（div 等）内 markdown 缺空行分隔被吞；用浏览器目检渲染确认，补空行即可，机械检查查不出 |
| 其他项目没有 scripts/ 结构 | 用 `--readme` 参数指向其 README 即可，不必复制脚本 |
