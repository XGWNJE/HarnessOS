# AI 编程时代的技术栈选型 Harness

提炼自百亿 Token 级 Vibe Coding 实战经验。适用于一切「要让 AI 高频生成、修改、验证代码」的项目。

## 第一性原理：选型看反馈闭环，不看生成能力

判断一项技术是否适合 AI 编程，关键不是「AI 能不能写出它的代码」，而是：

> **生成之后，能否快速检查、验证和修正。**

AI 不擅长「一次写对」，但非常擅长在**反馈足够明确**的情况下持续迭代。因此选型优先级：

1. **反馈是否明确、机器可判定**（编译器报错、类型检查、测试通过/失败，而非依赖人眼判断）
2. **反馈是否快**（工具链每快一点，高频迭代闭环被成倍放大）
3. **上下文是否集中**（结构、逻辑、样式能否在同一上下文中修改，减少 AI 在文件/范式间跳转）
4. **约束是否清晰统一**（对 AI 而言，清晰的约束和统一规则比无限自由更重要）
5. **生态与公开语料是否充足**（AI 对主流技术的理解深度远超小众技术）

## 推荐分层栈（Agent 应用）

| 层 | 技术 | 为什么 |
|---|---|---|
| 底层/性能敏感 | **Rust** | 严格类型系统 + 编译器检查提前暴露问题，给 AI 稳定明确的反馈，特别适合「生成—编译—修正」循环快速收敛；越接近文件/进程/网络/系统调用，错误代价越高，Rust 价值越明显 |
| 应用逻辑 | **TypeScript** | 静态类型将错误前置；npm 生态的网络效应（连 Deno 都回头兼容 Node/npm）；关注编译性能进展（如原生编译器），补上反馈速度一环 |
| 界面 | **React + Tailwind CSS** | React 组件化把界面拆成边界清晰的结构/状态/交互，公开代码多、AI 理解充分；Tailwind 把样式收敛为可组合、可预测的工具类，AI 不用在组件、样式文件、命名体系间跳转 |
| 运行容器 | **Electron** | Chromium（Agent 观察/操作 Web 的窗口）+ Node.js（连接本地系统/工具的执行层），是天然的 Agent 行动载体；过去的缺点（体积大、资源占用高）在 Agent 时代转化为优势——Agent 恰好需要完整、可编程、跨平台的行动环境 |

组合效果：Agent 可在相对集中的上下文中同时改结构、逻辑与样式，再通过类型检查和视觉反馈迅速验证。这套组合成为主流，不只是因为开发效率高，更因为**天然适配 AI 高频生成—修改—验证的工作方式**。

## 反面清单：选型时的坑

### Tauri（相对 Electron）
- 硬伤是**系统 webview 的不确定性**：不同系统、不同版本表现不一致；webview 有 bug 时自己无法修复，只能等系统升级（用户很难买账）
- 跨平台一致性差（正是 Electron 用打包 Chromium 换来的东西）
- 窗口/配置 API 有限、新开授权弹窗与文件下载需自行处理
- 实战信号：OpenCode 桌面端从 Tauri 迁回 Electron（「WebKit is asssss. Moving to Electron very soon.」）
- 结论：包体积减小的收益，抵不上稳定性与 Node.js 生态的损失。真正的严重 bug 轮不到你先发现——社区早弃坑了

### 自编译 Chromium（替代 Electron 跑 Chrome 插件）
- 源码+依赖数十 GB，官方要求预留 100GB 磁盘；首次全量构建几十分钟到数小时
- 三平台需分别维护工具链、补丁、签名、自动更新、回归测试
- 拿回的是底层能力，并不会自动得到完整 Chrome（Web Store、账号、策略、插件生命周期、权限治理都没有）
- 最终维护的是一条**浏览器厂商级别的内核与发行链路**，不是一个应用

### 通用警示
- **生态网络效应远比想象强大**：成熟生态（npm、Chrome 插件体系）是护城河，不要轻言替代
- **最危险的不是 API 不存在，而是半实现的 API**：方法存在、调用不报错、语义只实现一半——会在很远的下游以极难定位的方式失败。评估兼容性时对齐的是「可观察语义」（参数校验、错误作用域、事件投递、生命周期），不是方法名清单

## 选型决策流程

```
1. 定义任务形态：AI 高频迭代？长链路系统任务？一次性脚本？
2. 评估反馈闭环：该技术能否提供机器可判定的快速反馈？（编译/类型/测试/视觉回放）
3. 评估上下文集中度：AI 改一个功能要跨多少文件、多少范式？
4. 评估生态与语料：主流程度、公开代码量、AI 理解深度
5. 评估失败代价：错误越接近底层（系统调用、数据、权限），越要选强约束技术
6. 警惕「轻量替代」诱惑：问清楚它为了轻量牺牲了什么（一致性？生态？可控性？）
7. 查社区真实信号：GitHub issue、迁移公告、一线开发者的弃坑记录，比 benchmark 和榜单可靠
```

## 配套：长链路任务的收敛闭环

模型单次生成无法闭环复杂系统任务。可靠路径是搭一条**证据链**让 AI 反复收敛：

```
官方文档 → 上游源码 → 本地实现 → 自动化测试 → 真实环境运行 → 视觉回放 → 发现偏差 → 回到文档和源码
```

三要素缺一不可：**模型能力、工具链、多模态（视觉验证）**。长链路任务尤其依赖三者协作。

## 心智模型速查

- 榜单看看就好，真实干活水平只有踩过坑才知道
- 模型强不强是一回事，能不能把它带到正确方向是另一回事——拼的是人的认知和判断力
- Token 消耗量 ≠ 产出价值，它只是「计算与探索消耗」
- 每个程序员都应构建自己的 harness 工程，随大模型一起迭代进化
- AI 时代推翻重写成本大降，兼容历史包袱只会是负债——但重写前先确认新底座可验证
