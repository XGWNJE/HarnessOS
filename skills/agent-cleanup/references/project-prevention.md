# 预防规则落地

用于用户要求项目治理或预防改造时。目标是让后续 Agent 有简明的约束，正在使用的构建／验证入口实际执行这些约束；仅做技能维护或只读分析不修改项目。

## 从规则到执行入口

| 项目要明确的约束 | 执行位置 | 检查实际行为 |
|---|---|---|
| 新任务、重试先复用；需要隔离时使用有限槽位 | 源码副本／worktree 创建入口 | 同一配置重复执行，槽位数不随轮次增加 |
| 可写源码和输出同一时刻有明确所有者 | 任务调度、租约／互斥 | 并发请求等待或拒绝，不覆盖在用槽位 |
| 配置变化导致缓存失效，新源码重新验证 | 安装、编译及组装入口 | 修改输入后新产物反映变化；旧成功记录不直接放行 |
| 有界缓存、普通现场和日志，磁盘余量不足不能另建副本绕过 | 创建前及必要的构建阶段 | 达到预算时仅处理获准闲置项，否则明确停止依赖的操作 |
| 成功、失败、取消和超时都收尾 | 真实退出路径、finally、CI 收尾 | 进程退出、证据可读、槽位可接管；状态不明时保持占用保护 |
| 持久资产和有效证据按项目规则保护 | 资源分类和回收候选选择 | 业务数据、配置、签名、模型及回滚引用不进入通用回收 |

只选择项目实际需要的机制。串行任务通常不需要复杂池；现有构建缓存已能复用时不另造缓存层。检查器应读取同一配置，避免规则、脚本和测试分别维护不同上限。

## 精简项目规则

将下面的含义融入已有章节，不必逐字复制：

> Agent 创建验证副本、构建目录或重试现场前，先通过项目维护入口复用可用资源并检查预算；确需隔离时使用受控槽位，不按轮次无界新增。缓存按工具输入失效，检查结果绑定本次源码。各类退出均确认进程、保存必要证据并按既定生命周期释放资源；达到边界且无法安全处理时报告具体阻塞项，不另建副本绕过。业务持久数据、配置、模型、正式包、回滚点和有效证据按各自规则保护。

落到具体项目后，写出实际入口链接和适用范围。容量、保留数量、期限及资源路径尽量只由已有配置或脚本维护；不要保留不可执行的占位值，也不要把某次测得的目录大小永久写进规则。

规则里“每次全新环境”“永久保留所有现场”可能分别服务于可信度或取证要求。先查明用途：能保留目标并改进实现就同步调整；依赖明确隔离、发布或保留边界时，保留该要求，在允许范围内复用和限制增长，不能以省空间为由静默放宽。

“旧垃圾由 owner 自行删除”与“新构建内部资源按既定生命周期维护”需要分开写清；前者不阻止设计受控的新流程，后者也不授权清理历史未知目录。确需改变原有明文边界时，具体说明冲突及必要授权，不将整项治理停在泛泛确认上。

## 最小验收与交付

- 复用：连续执行同一配置，记录目录数、结束占用和必要的峰值；缓存命中符合预期。允许正常缓存热身，不要求所有轮次字节完全不变。
- 正确性：至少覆盖影响本次复用判断的输入变化；不能只断言新增了某段规则或函数名。
- 预算与异常：对本次改造涉及的满额、重试、失败／取消或并发路径做最小真实验证；异常没有制造新副本绕过上限，没有丢失之前的有效证据。
- 集成：调用链确实经过新逻辑；已有项目检查与 CI 按需要接入。若只写了规则、入口未改或关键异常路径未验，明确标为未完成，而非“已预防”。

收尾只保留当前规则、维护入口和必要证据。区分“未来增长已受控”“存量已回收”“技能支持该流程”，三者分别需要证据，不能互相代替。
