# Agent 空间治理

目标是把资源生命周期落实到项目规则和实际执行入口，让新增副本与重复构建从开始就受控，同时保持源码、构建结果和验收证据可信。已有膨胀需要归因和存量处置；尚未膨胀也可以检查并补齐预防机制。

## 先确定本轮范围

区分诊断、方案实验、项目治理和存量清理。用户要求治理、优化或建立预防机制时，在授权范围内完成项目规则、执行入口和验证的闭环，不止给分析或建议；明确仅分析／试调用时保持项目只读。仅要求修改本技能时不顺带改造其他项目。

实际删除遵循当前授权和项目规则；本技能不增加删除、重置用户工作树、改变发布门禁或修改全局规则的权限。项目明确要求 owner 自行清理时，存量只交付精确清单及默认预览的脚本，继续完成新生成流程的预防改造；不能借改写项目规则扩大删除授权。

## 在生成之前落实项目规则

新增或调整 Agent 验证、审查、构建、并行与重试入口时，先检查资源生命周期，不等磁盘异常：

1. 阅读项目 `AGENTS.md` 及现有构建、CI、资源维护约定，找到真实调用入口。识别“每次新建”“完整现场永久保留”“失败继续复制”等规则与代码是否会造成无界增长。已规定复用而代码未执行，也属于待修问题。
2. 按实际技术栈与并发需要选择最简单的复用方式，明确资源位置、所属任务、复用条件、数量／容量／期限中必要的边界、失败保护和回收入口。具体参数依据现有单轮占用、并发和磁盘余量制定，不一律套固定大小。
3. 将预防要求精简写入或合并到项目级 `AGENTS.md`，供以后各任务遵守；配置数值和实现细节放已有配置／脚本或维护文档，规则只链接唯一入口。合并冲突、重复的旧条目，不叠加另一套长期保留规则；无需为套模板新建文档。
4. 同步改造正在被调用的脚本：创建前复用与预算检查、构建期间互斥和缓存失效、各类退出后的证据归档与槽位释放。只有规则文字、未被调用的回收函数或一次性清理脚本，不算预防已生效。
5. 用重复执行和必要的失败路径验证实际行为，再按项目要求完成文档和本地提交。报告规则变化的原因、行为影响和未覆盖项，不把方法论更新冒称任何项目已完成改造。

实施项目规则改造时读取 [预防规则落地](references/project-prevention.md)。日常只做与当前入口有关的轻量检查；没有增长迹象时，不为每次构建重复全盘扫描、引入复杂调度平台或扩大清理范围。

## 从实际占用追到生成入口

1. 核实真实根目录、主线和未提交修改，记录扫描时间。分别测量主工作区、Git 对象库、外部 Agent 工作树及相关缓存，不把 Git 仓库大小与文件夹大小混为一谈。
2. 先看非重叠的一级目录，再深入大头；识别外层副本中的嵌套副本。可运行只读的 [inventory.py](scripts/inventory.py)：

   ```text
   python <本技能目录>/scripts/inventory.py <目标目录> --depth 3 --output <工作目录>/inventory.json
   ```

   默认不跟随符号链接、Junction 和其他 reparse point。`--dedupe-hardlinks` 额外统计扫描范围内唯一文件的逻辑字节，耗时和内存会增加。逻辑大小、去重逻辑大小、已分配空间和实际可释放空间分别表述；扫描失败必须注明不完整。
3. 将大目录对应到生成命令、调用者、创建时间、所属任务、当前进程和外部引用。搜索 `mkdtemp`、`worktree add`、`clone`、逐提交输出路径、重试循环、安装依赖和构建入口；检查成功、失败、取消、超时、崩溃之后各留下什么。
4. 把根因写成可核验的链条，例如：每次重试新建源码副本 → 每份独立安装依赖和编译 → 无数量／容量边界 → 失败现场也永久保留。主因未确认前，不先运行全量重建或重写 Git 历史。

## 分开管理四种资源

| 类别 | 生命周期与复用依据 |
|---|---|
| 源码工作区 | 明确提交、干净状态、所属仓库及并发占用；源文件变了必须重新绑定身份 |
| 依赖及构建缓存 | 编译器／包管理器负责输入失效；允许重建、应有容量或期限边界 |
| 验证证据 | 保存检查记录、实际引用的日志／探针输出、摘要及来源；不能只留一份 JSON 就声称完整 |
| 持久资产 | 业务数据、配置、凭据、模型、正式包及有效回滚点按项目规则管理，不混入通用缓存回收 |

未被 Git 跟踪、被忽略、目录名含 `tmp`，均不足以证明可删除。区分“检查通过的证明”与“可重新复现整个现场”；它们需要保留的内容不同。

## 用最小实验选择复用形态

优先比较能覆盖实际大头的候选，不为比较而搭平台：

- **固定路径的受控验证工作区／小型池**：适合同一可信项目反复串行验证，能同时复用 Rust、Gradle、.NET 等本地状态。源码按目标提交切换，证据另存；池大小按真实并发需求确定，重试不能自动扩池。
- **临时源码副本＋共享工具缓存**：适合要求全新源码树或需要并行的验证。缓存按项目及影响兼容性的配置分组，避免逐提交／逐轮创建永久缓存。仅共享受工具支持、并发语义明确的缓存。
- **现场轮换＋证据归档**：适合已有大量存量、需要保留排错能力的项目。完整现场的数量、保留条件及失败保护可配置，不把“最近一次成功＋一次失败”写成所有项目的固定规则。

按所用技术栈读取 [复用与验证要点](references/reuse-patterns.md)。不同项目的最优组合可能不同，固定目录也需要回收策略；不要直接宣称固定目录一定最快或占用永不增长。

先满足正确性和隔离要求，再按重复执行后的增长量、峰值占用和改造成本选择方案。实验记录同一口径的基线、峰值／结束占用、耗时、实际缓存命中和正确性：

1. 至少重复运行，确认缓存被使用、目录数量不随轮次递增。对比非重叠目录，避免将已有共享资源重复算作节省。
2. 验证源码变化会重建且新产物反映变化；涉及依赖复用时再覆盖锁文件／配置变化。复用工作树还要检查删改文件残留，不只比较退出码。
3. 并发复用必须验证互斥或隔离；失败／取消后不破坏之前的证据，也不留下无人接管的运行实例。进程未确认退出时不转交同一可写工作区。
4. 归档证据先复制到独立位置，核对文件摘要和所有引用，并运行适用的真实校验入口。结构校验、历史记录校验、当前源码门禁和重新构建分别报告，不互相替代。

微型样本只能证明机制可行；容量模型是估算。将结果明确分成“实测”“测算”“待项目验证”，不把样本节省比例、旧证明或日志成功字样外推为全项目验收。

## 实现有界生命周期

项目治理时，在实际生成入口修复，并与项目规则保持一致：

- 创建前先查可用的受控工作区；限定项目、路径和所有者，拒绝覆盖用户改动。使用可靠互斥或租约，并处理异常退出；不能只凭旧 PID 或锁文件年龄自动认定闲置。
- 编译缓存沿用工具的失效机制；依赖变化、编译配置及目标架构必须进入复用判断。正式产物按现有来源、协议、签名及摘要门禁验证。
- 成功、失败、取消、超时都进入收尾：先关闭本轮已不用的进程，再固化证据、释放槽位，按获准规则回收可重建资源。失败现场可保护，但需明确解除条件，不能无限累积。
- 容量／数量／期限采用项目需要的最小组合；同时考虑高峰临时空间和磁盘余量。达到边界先淘汰符合条件的闲置项；若不允许自动回收或候选都受保护，给出具体阻塞项，禁止静默另建副本绕开边界。
- 日志和普通轮次输出也要有保留范围，可压缩或轮换；有效验收／发布证据按引用保留，不默认永留整个构建现场。
- 记录资源位置、所有者、用途、预算及维护入口，保持文档简洁。已有 CI 接入占用趋势、重复运行增长及收尾检查；没有 CI 时按项目规模建议轻量接入，不另建复杂平台。

存量迁移与新机制分开处理。复用机制生效不会自动释放旧目录；回收前重新核对绝对路径、链接、唯一提交、未提交／忽略文件、进程及必要证据，优先使用 Git 或工具自己的维护入口。Windows 文件操作保持同一 shell 和路径语义，不把枚举结果拼给另一 shell 删除。

## 依据效果自我迭代

每次调用都根据本轮已有证据检查效果；正常完成且没有新发现时不强行修改技能。以下情况触发复盘与修订：实际占用／峰值或重复增长未改善、治理引入过大耗时或破坏复现，命令／扫描／回收失败，以及其他项目出现现有策略未覆盖的生成机制。

用户已授权在上述触发条件下主动维护本技能的说明、参考策略和必要脚本，无需为普通修订反复确认。项目只读范围与技能维护分开；用户明确要求完全只读或不改技能时不写回。自我修订不扩大项目删除权限，不修改全局规则，不绕过审批、发布门禁或数据保护。

触发后读取 [效果复盘与技能迭代](references/iteration.md)：确认失败层级或新根因 → 修正最小策略／工具 → 用同口径工作负载验证效果和保护条件 → 将可迁移结论写回技能并合并旧内容。只影响当前项目的路径、数值和例外留在项目；新原因不能强套既有三种复用形态。无验证结论的候选不得升级成默认删除策略。

同一失败没有新证据时停止重复尝试；尤其不能通过改写规则、换工具／目录、关闭校验来绕过拒绝或伪造成功。修订无效或引入回归时只撤回本轮修改，继续独立可做的项目工作并说明缺口。迭代内容保持当前有效状态，不积累逐轮复盘流水或项目私密资料。

## 交付

简洁说明：主要生成链条或事前发现的缺口；选中方案及取舍；项目规则与实际入口各改了什么；实测增长／节省与估算的区别；重复执行及异常收尾结果；旧存量是否仍在、是否实际删除。触发自我迭代时补充技能修正及验证边界，不把技能更新等同于项目已修好。仅方法论／实验任务无需修改项目规则、部署或生成额外台账。
