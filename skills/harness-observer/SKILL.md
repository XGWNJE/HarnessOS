# Harness Observer（静默观察者）

> 写法：目标模式——只描述想要的目标与验收标准，不规定具体做法；做法由模型按情境自决。

本 skill 想要的结果：**有规则价值的观察被完整、准确、安静地传递进 HarnessOS 原料区，当前任务完全不受干扰**。一切静默观察信号统一由本 skill 记录。

## 环境前提

此段仅声明事实，不规定 Agent 行为。

- **HarnessOS 仓库**需可写访问。本地默认位置 `D:\ObjectCode\HarnessOS`（Windows）或 `~/ObjectCode/HarnessOS`（Linux/macOS）。Agent 按以下优先级定位：① 当前项目 AGENTS.md 中如有 HarnessOS 路径声明则取之；② 按上述默认位置依次尝试；③ 遍历 `~/` 与 `D:\` 根目录下名为 `HarnessOS` 的目录。路径不可写时本 skill 不可用。
- **文件写入工具**可用（Write / bash echo / PowerShell Out-File 等——任一即可）。
- **无网络依赖**：本 skill 只写本地文件，不调网络 API。

## 目标与验收标准

- **静默零干扰**。验收：当前任务的对话中不出现对本 skill、观察记录动作或 HarnessOS 的任何提及；不请求确认、不中断流程，当前任务的任何决策不因观察而改变。
- **唯一观察通道**。验收：任何项目中的静默观察信号（含原 scope-guard 语义失败信号）全部经本 skill 落盘，不存在第二个观察通道或记录位置。
- **写入只落在原料区**。验收：观察只追加写入 `D:\ObjectCode\HarnessOS\notes\inbox\` 下的文件；未运行 git / sync / publish；HarnessOS 其他任何文件未被修改；当前项目的代码、配置、文档未被改动——观察与当前任务交付物完全隔离。
- **复述时机受控**。验收：观察结果的复述只发生在 owner 于 HarnessOS 仓库主动要求自检时；本 skill 不主动发起复述或评审。
- **信号应记尽记**。验收：命中下表四类信号的观察都被记录；拿不准类型的按 `归纳式原料` 记，留待评审归并。
- **脱敏**。验收：记录中不含密钥、token、凭据、私密 URL，不含完整提示词和工具输出原文。
- **语义失败可归纳**。验收：语义失败条目写明根因和被违反的假设，能直接作为「防再犯」规则的原料。
- **查重有效**。验收：同主题观察只有一条记录；再次观察到时该条 `重复计数` +1 并附本次日期与一句话新证据，不新开条目；计数作为 owner 验收时的参考权重（重复次数越多越值得固化），不对应任何固化门槛。
- **记录成本受控**。验收：单条观察两分钟内记完；超过说明在过度加工，留下粗糙版即止。
- **只记不加工**。验收：归并、提炼、发布均未由本 skill 执行，全部留给 HarnessOS 的评审流程。

## 观察信号分类（事实约定）

| 信号 | 类型 | 说明 |
|---|---|---|
| owner 重复纠正同一问题（≥2 次）但从未明说 | `待确认` | 声明式规则的候选态，附每次纠正的日期与场景；owner 确认前不得固化 |
| owner 明确表达的偏好、习惯、验收标准 | `声明式规则` | 意图型，附原话要点 |
| 踩坑 + 当时判断 + 实际结果 | `归纳式原料` | 经验型，由 owner 评审验收后固化 |
| Agent 自身语义失败（假设被违反、目标错误、路径错误、范围错误） | `归纳式原料` | 原 scope-guard 信号。同一根因重复出现时用重复计数累计，是「防再犯」规则的主要原料 |

## 机制（实现约定，非规定）

以下是与 HarnessOS 评审流水线对接的既定机制——去掉它们观察无法落盘或无法被评审消费，因此作为机制保留，而非做法偏好：

- 落盘位置：HarnessOS 仓库路径下的 `notes/inbox/YYYY-MM-DD.md`。Agent 按环境前提中声明的优先级定位 HarnessOS 路径，首次写入后记住该路径供本次会话复用。写入前确保 `notes/inbox/` 子目录存在（不存在则创建）。文件编码 UTF-8，已存在则追加。这是原料区的唯一入口。
- 查重数据源：写入前对照 `notes/inbox/` 近 30 天文件查找同主题条目——这是查重可用的唯一数据源。
- 记录格式：评审流水线解析 inbox 条目的既定契约：

```markdown
## <一句话主题>
> 日期：YYYY-MM-DD
> 场景：语言/工具/任务类型
> 类型：待确认 | 声明式规则 | 归纳式原料
> 来源项目：<项目名或路径>
> 重复计数：<n>（同主题再次观察到时 +1，供 owner 验收参考）

观察事实（做了什么、owner 怎么纠正、结果如何）。脱敏：不写密钥、token、私密 URL。
```

## 环境自检

本 skill 被触发后（或静默观察块常驻生效时），在首次观察落盘前无声确认：

1. HarnessOS 路径可定位（按环境前提中的三层优先级尝试）
2. `notes/inbox/` 目录存在且可写（具体为：能创建或追加写入一个 UTF-8 .md 文件）

自检通过 → 不报告给用户，直接进入静默观察状态。
任一前提不满足 → 见下方「失效模式」。

## 失效模式

| 前提失败 | 降级行为 |
|---|---|
| 全部默认路径均不存在或不可写 | **静默降级，不写入。** 不影响当前任务。在本次会话**结束时**向用户追加一条私密提醒："本次会话中有（N）条观察未能落盘——HarnessOS 路径不可写。请检查仓库位置后手动记录或下次自检时让我复述。"提醒中不含对话中已做过的任何决定或信息，只是数量提醒。Agent 自身**记住**未能落盘的观察主题（仅主题），以备 owner 后续要求复述。 |
| `notes/inbox/` 目录可写但当日文件被锁（另一个进程正在写入） | 等 2 秒后重试一次。仍失败则追加到同目录 `YYYY-MM-DD-bak.md`（侧通道文件，评审时会被一起扫描）。 |
| 查重时无法读取近 30 天文件（权限不足/文件损坏） | 不阻塞写入。在本次写入的条目尾部标注 `> 注意：查重未完成（inbox 文件不可读）`。减少重复记录但允许新条目进入。 |

以上全部为静默行为——降级过程本身不在对话中出现。
