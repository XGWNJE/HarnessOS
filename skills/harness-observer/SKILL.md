# Harness Observer（静默观察者）

在任何项目工作时本 skill 常驻生效。职责只有一个：**把有规则价值的观察静默传递给 HarnessOS**，绝不干扰当前任务。

## 静默纪律（最高优先级）

1. 不在当前任务的对话中提及本 skill 的观察、记录动作或 HarnessOS。
2. 不请求确认、不中断流程、不改变当前任务的任何决策。
3. 只追加写 `D:\ObjectCode\HarnessOS\notes\inbox\` 下的文件；不运行 git / sync / publish，不修改 HarnessOS 其他任何文件。
4. 观察结果的复述只发生在两个时机：owner 在 HarnessOS 仓库主动要求自检时、每周评审时（由评审流程读取 inbox，不由本 skill 主动发起）。

## 观察信号与分类

| 信号 | 类型 | 说明 |
|---|---|---|
| owner 重复纠正同一问题（≥2 次）但从未明说 | `提议` | 声明式规则的候选态，附每次纠正的日期与场景 |
| owner 明确表达的偏好、习惯、验收标准 | `声明式规则` | 意图型，附原话要点 |
| 踩坑 + 当时判断 + 实际结果 | `归纳式原料` | 经验型，走三门槛 |

拿不准类型时按 `归纳式原料` 记，评审时再归并。

## 记录格式

追加到 `D:\ObjectCode\HarnessOS\notes\inbox\YYYY-MM-DD.md`（按观察发生日，一天一个文件）。已存在则追加，文件编码 UTF-8：

```markdown
## <一句话主题>
> 日期：YYYY-MM-DD
> 场景：语言/工具/任务类型
> 类型：提议 | 声明式规则 | 归纳式原料
> 来源项目：<项目名或路径>
> 重复计数：<n>（同主题再次观察到时 +1）

观察事实（做了什么、owner 怎么纠正、结果如何）。脱敏：不写密钥、token、私密 URL。
```

## 查重（写入前必做）

1. 先读 `notes/inbox/` 近 30 天文件，找同主题条目。
2. 找到同主题：更新该条 `重复计数` +1，并在条目末尾追加一行本次日期与一句话新证据；不新开条目。
3. 未找到：按上面格式新开条目。
4. 重复计数直接服务于归纳式规则的「重复 2 次以上」门槛，必须准确。

## 边界

- 不写当前项目的代码、配置或文档；观察与当前任务交付物完全隔离。
- 一条观察两分钟内能记完，超过说明在过度加工——停下来，记粗糙版。
- 本 skill 只负责「记」；归并、提炼、发布全部留给 HarnessOS 的评审流程。
