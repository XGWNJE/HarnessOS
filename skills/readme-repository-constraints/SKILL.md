# README 模板

为软件、开发工具和数据项目创建或改写 README 时使用本技能。目标是让第一屏先讲清项目身份、用途和开始方式，再按仓库交付方式组织细节。

不用于普通文章、个人说明页、没有代码或数据交付物的仓库，或用户明确指定另一套 README 规范时。

## 先选仓库类型

根据仓库实际交付物选一个主模板；混合仓库按主要使用者的第一任务选择。

| 类型 | 使用资产 | 首屏重点 |
| --- | --- | --- |
| 应用项目 | `assets/application.md` | 给谁用、现在能否试、从何开始 |
| 库与 SDK | `assets/library-sdk.md` | 安装命令与最小可运行调用 |
| 命令行工具 | `assets/cli.md` | 输入、命令、成功时的输出 |
| 数据与机器学习 | `assets/data-ml.md` | 主结果、数据与可复现路径 |

将资产作为结构起点，而不是照抄。替换全部 `{{占位符}}`；没有可靠事实支撑的小节直接删掉。

## 统一头部

所有仓库类型的 README 头部按以下顺序组成，正文从其后的二级标题开始：

1. **项目图标**：使用仓库已有的正式图标，放在一级标题内、项目名称左侧，与项目名称保持同一行；确无正式图标时省略，不生成或借用无关图片。
2. **项目名称**：与项目图标共用同一个一级标题，写作 `# <img ...> 项目名称`，图标与名称之间不换行。图标的可见高度应与项目名称文字的可见高度一致，垂直居中、视觉上处于同一行，不得明显高出文字或撑高标题行。使用 `height` 控制尺寸并保持原始宽高比；模板中的 `height="32"` 仅为起点，须按目标渲染器的标题字号和图标自身留白调整，不能把图片画布尺寸当作可见图形高度。
3. **项目简介**：用一两句话说明项目是什么、用户能用它做什么。
4. **文档导航标签**：用一行 Markdown 链接指向 README 内实际存在的主要章节，以 `·` 分隔；章节删改时同步更新标签和锚点。
5. **项目徽标（徽章 / badges）**：放在导航标签下方，展示已核实的版本、平台、许可证或构建状态等，使用可点击的徽章图片并链接到对应依据或入口；不以纯文字元信息行替代徽标区，不添加无法核实的徽标。

安装命令、下载或在线体验入口、实验指标和适用场景等放入对应正文小节。徽标使用可维护的 SVG/PNG 或徽章服务，核对图片与目标链接，提供有含义的替代文本；不使用 AI 生图制作徽标。

## 不可省略的约束

- 先核对仓库内已有的名称、正式图标、运行命令、许可证、版本、链接和截图；不猜测、不编造指标、徽章、路线图、安装命令或在线地址。
- 用户要求重构或全面刷新 README 时，从当前项目的代码、配置、测试、发布记录和有效文档重新梳理内容与结构；旧 README 只作待核对的线索，不沿用其章节、措辞或未经证实的结论。
- 用尽可能直白的话说明用户能做什么、怎样操作、会得到什么；只有准确表达确实需要时才使用术语，并在首次出现时用白话解释。
- 逐项核对 README 中的事实是否仍与项目现状一致，尤其是功能、平台、目录、命令、依赖版本、配置、发布状态和外部链接。需要时查实时权威来源，并区分已验证事实与待确认信息。
- 重新制作演示界面或截图属于耗时的独立工作；除非用户要求，不把它作为刷新 README 的默认步骤。仍须核对已有截图或演示的路径与内容是否适用；无法确认时标明，不用旧画面暗示当前功能。
- 确实需要新架构图、流程图或数据流图来解释项目时，使用现有 `archify` 技能，并以项目事实为依据；不要为了装饰而加图。
- 不生成或添加氛围图、装饰性横幅、伪产品图或带文字的生图。截图、架构图和流程图只在能解释具体功能、接口或操作时使用。
- 导航、命令和详细指标使用 Markdown/HTML 文本，不烘焙进图片；头部徽标可用图片显示已核实的版本、平台、许可证和状态等信息，不受此限制。
- 开场使用具体、可验证的说法：用户做什么、输入什么、得到什么。避免“赋能”“一站式”“极致体验”“提升效率”等没有证据的营销语。
- 代码块和命令必须与仓库现状相符，且要说明必要前提、预期结果或失败提示。
- README 面向使用者；贡献、开发、发布和架构细节放在使用路径之后，或链接到专门文档。

## 写作与验证

1. 从仓库文件和已有文档提取事实，并选定一个模板。
2. 让第一屏可在一分钟内回答：这是什么、适合谁、怎么开始。
3. 仅保留项目确实支持的功能、平台和流程；对于限制或不适合的使用场景，直接说明。
4. 提交前检查：头部顺序符合「项目图标 + 项目名称（视觉等高、垂直居中且同一行） → 项目简介 → 文档导航标签 → 项目徽标」，图片（含徽标）和目标链接有效、导航锚点与实际章节一致、命令没有明显矛盾、占位符已经清空。有正式图标时，在目标 README 渲染器中检查图标与文字的实际高度和对齐；无法预览时明确标为未验证，不以尺寸属性相同代替视觉验收。

如果缺少关键信息，保留简短待补标记或询问用户；不要用看似完整的虚构内容填满 README。
