# README 仓库模板约束

为软件、开发工具和数据项目创建或改写 README 时使用本技能。目标是让第一屏先讲清项目身份、用途和开始方式，再按仓库交付方式组织细节。

不用于普通文章、个人说明页、没有代码或数据交付物的仓库，或用户明确指定另一套 README 规范时。

## 先选仓库类型

根据仓库实际交付物选一个主模板；混合仓库按主要使用者的第一任务选择。

| 类型 | 使用资产 | 首屏重点 |
| --- | --- | --- |
| 应用项目 | `assets/application.md` | 给谁用、现在能否试、从何开始 |
| 库与 SDK | `assets/library-sdk.md` | 安装命令与最小可运行调用 |
| 命令行工具 | `assets/cli.md` | 输入、命令、成功时的输出 |
| 数据与机器学习 | `assets/data-ml.md` | 主结果、数据与可复现路径 |

将资产作为结构起点，而不是照抄。替换全部 `{{占位符}}`；没有可靠事实支撑的小节直接删掉。

## 不可省略的约束

- 先核对仓库内已有的名称、运行命令、许可证、版本、链接和截图；不猜测、不编造指标、徽章、路线图、安装命令或在线地址。
- 首屏必须有项目名的一级标题。若仓库已有正式图标，可在标题前使用它；没有图标时只显示项目名称。
- 不生成或添加氛围图、装饰性横幅、伪产品图或带文字的生图。截图、架构图和流程图只在能解释具体功能、接口或操作时使用。
- 链接、版本、指标、命令和状态由 Markdown/HTML 渲染，不放进图片。
- 开场使用具体、可验证的说法：用户做什么、输入什么、得到什么。避免“赋能”“一站式”“极致体验”“提升效率”等没有证据的营销语。
- 代码块和命令必须与仓库现状相符，且要说明必要前提、预期结果或失败提示。
- README 面向使用者；贡献、开发、发布和架构细节放在使用路径之后，或链接到专门文档。

## 写作与验证

1. 从仓库文件和已有文档提取事实，并选定一个模板。
2. 让第一屏可在一分钟内回答：这是什么、适合谁、怎么开始。
3. 仅保留项目确实支持的功能、平台和流程；对于限制或不适合的使用场景，直接说明。
4. 提交前检查：图片和文档相对路径有效、标题锚点与目录一致、命令没有明显矛盾、占位符已经清空。

如果缺少关键信息，保留简短待补标记或询问用户；不要用看似完整的虚构内容填满 README。
