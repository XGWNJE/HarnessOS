# Codex 历史会话恢复

目标：在不覆盖现有会话的前提下，区分“列表不可见”“正文缺失”和“Provider 不可续聊”，恢复可恢复的数据并用 Codex App 实际读取验收。

## 验收标准

- 分别核对 rollout 正文文件、SQLite 线程索引、Provider/账号信息及项目可见性元数据，不把索引存在等同于正文存在。
- 写入前建立可恢复备份；合并只追加，不覆盖已有文件或数据库行，并按 thread ID 与内容哈希识别重复和冲突。
- `sync` 只修复当前 Provider 下的元数据与可见性；`restore` 只回滚错误同步，不把两者混用。
- 最终在 Codex App 中打开抽样旧任务并读取正文；只验证文件数、数据库行数或列表出现不算恢复完成。
- 明确说明跨 Provider 或账号的加密正文可能无法解密，禁止把改成 `custom` 当成重新加密手段。

## 参考流程

1. 只读盘点当前数据目录、SQLite 数据库、rollout 目录、切换工具备份及当前 Provider；记录数量与 thread ID 集合。
2. 将问题分层：索引缺失、rollout 缺失、项目/Provider 元数据不可见、正文解密失败。先证明是哪一层，再选择修复动作。
3. 对候选备份计算哈希并解析 thread ID；已有同 ID 同哈希则跳过，同 ID 不同哈希则停止并报告冲突。
4. 对将修改的文件和数据库建立带时间戳备份，然后只追加缺失 rollout 或索引；不得以旧快照覆盖当前目录或数据库。
5. 需要修复当前 Provider 可见性时执行 metadata sync；结果错误时才用对应备份 restore。
6. 复查集合差异，并在 Codex App 中打开代表性任务，确认正文实际可读、当前任务未受损。

## 边界

- 不删除无法识别或暂时不可见的历史数据。
- 不承诺跨 Provider/账号恢复加密内容；保留原始数据并报告限制。
- 不在日志、报告或技能资产中记录会话正文、凭据或 Provider 密钥。
