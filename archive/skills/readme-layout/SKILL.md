# README 版式

目标：给每个项目产出一份信息完整、结构规范、视觉克制的中文 README 首页。版式分为「必选结构」与「规范结构」两层：**必选结构**（产品图标、徽标、界面展示）按优先级取舍，不因项目有无素材而变形；**规范结构**（标题、定位、正文分节、文档导航）遵循 README 文档的规范写法，携带适合该项目的章节，不强行凑齐。同时遵守项目文档「责任分区」：README 只承载面向用户的定位、入口、截图与文档导航，不放入操作细节、Agent 执行规则或历史记录。

## 必选结构（必须有，按优先级取舍）

### 1. 产品图标

- 项目有产品图标（应用图标 / logo / 品牌图）时：**必须放在最顶部居中**，尺寸约 80–100px，用仓库内相对路径引用，并给出 `alt`。
- 项目没有产品图标时：不占位、不画饼，标题直接居中。
- 视觉层级：图标 > 标题 > 一句话定位语。

### 2. 徽标（badges）

- **必带**，但不能凑数：只加「合适」的徽标，拿不准的宁可不加。
- 合适的判断标准（满足其一即可）：
  - 项目事实：版本（来自 package.json / gradle 等实际版本号）、许可证（license 字段）。
  - 平台/架构：有明确平台或 Client/Host 角色区分的，用 shields.io 官方 logo 徽章表达。
  - 技术栈：技术栈稳定且能确认版本号（从锁文件、构建脚本读取，不猜测）的才加。
  - CI/自动化：仓库有可用的 CI workflow 时加状态徽章并链接到 workflow 页。
- 不合适的典型：无法确认版本号的技术、未使用的服务（如 codecov 但无覆盖率上传）、与项目无关的营销徽标。
- 所有徽标 URL 在提交前用 HTTP 请求逐个验证（期望 200），坏链不提交。
- shields.io 静态徽章格式：`https://img.shields.io/badge/<label>-<value>-<color>?logo=<icon>&logoColor=white`，带 logo 的优先。

### 3. 界面展示（截图）

按以下优先级取素材，取到哪级用哪级：

- (a) 用户主动提供截图：直接用，完整保留。
- (b) 用户没提供但项目里有历史截图（`screenshots/`、`docs/`、`assets/` 等）或可以调用自动化流程生成：用仓库内的真实截图。
- (c) 两者都没有：该区块**待定**——不编造截图、不用占位图、不留空框，在交付说明中明确告知用户待补。

截图展示统一用居中表格（多端/多状态并排），每列加 `alt` 说明；单张图可居中单列。

## 规范结构（按 README 规范写法携带，适合才放）

### 标题与定位

- 标题：项目名，无图标时居中。
- 定位语：标题正下方一行短句，说明「什么场景下的什么角色」，一句话讲清价值，不展开细节。
- 可选一行副语：用一句话点出最核心的价值主张或差异化，不重复定位语。

### 正文分节（按项目实际取舍，不强制全部出现）

- **它解决什么 / 项目干什么**：问题场景 → 产品定位 → 3–5 条核心能力（每条一句话、加粗开头）。
- **核心特性 / Features**：与上一节不重复时使用；通常合并进"它解决什么"。
- **架构 / 工作方式**（如适用）：客户端/服务端、端到端链路等，用文字或简单图示，不放代码细节。
- **当前状态 / 开发方向**（如适用）：当前阶段、已收敛范围、下一步。只写事实，不写计划当成果。
- **快速开始 / 安装 / 使用**：入口命令用表格或代码块呈现；操作细节不展开（指向项目规则文档）。
- **配置 / 开发**（如适用）：面向贡献者的构建、测试、运行入口；深水区内容指向专题文档。
- **界面展示**：见必选结构第 3 条。

### 结尾

- **贡献指南 / 参与**（如适用）：指向贡献文档或维护者入口，不内联大段流程。
- **许可证**：项目有明确 license 时放一行（与徽标一致）；无许可证不编造。
- **文档导航 / 文档地图**：结尾列出项目各文档的职责一句话说明 + 相对路径链接。有文档才列，不虚设。

## 责任分区（必须遵守）

- README 只负责「项目是什么、如何开始、文档导航」；**不放入**操作细节、完整规则、历史记录。
- 操作约束、验证、维护事实归 AGENTS.md；变更历史归 CHANGELOG.md；专题事实归专题文档——这些只用链接或简短指针指向，不复制正文。
- 项目没有某类文档时，不为满足模板而新建；先确认是否真的需要一个新的事实主人。
- 同一事实只有一个主人；其余文档只保留链接或简短指针。

## 验收标准

- 必选结构（图标/徽标/界面展示）齐全且顺序正确；有图标必居中显示，无图标标题居中且无空洞。
- 规范结构按项目实际携带，章节合适、不强行凑齐；内容分层符合责任分区（README 不承载操作细节与历史）。
- 徽标都是「合适的」且 URL 全部验证可解析；版本号、技术栈版本与仓库实际配置一致，不猜测。
- 界面截图来自真实素材；无素材时明确标注待定并反馈用户，不伪造。
- 图片路径在仓库内真实存在；链接相对路径正确；README 渲染后无坏图、无坏链。
- 文档地图路径存在、职责准确；入口、命令、依赖或目录变化时同步更新它们的唯一主人。

## 边界

- 只做 README 的组织与呈现，不创建项目规则体系、不改变其他文档的事实归属。
- 徽标、截图、版本号都必须有事实来源；找不到事实时不编造，明确反馈缺口由 owner 决定。
- 用户已有明确版式要求时，以用户要求为准；本技能规则是默认基线。
